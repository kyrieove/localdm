# 平板分发第一期方案

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> 本项目沿用用户指定分工：Codex 写方案和审查，DeepSeek 实现、构建、测试。上面的通用技能提示不改变分工，也不授权本轮实施。

**Goal:** 玩家扫码加入本机局域网页面，认领角色，阅读整本角色本，从完整名称列表点击并查看对应单张线索卡，同时只读查看公共对话和当前环节。

**Architecture:** WPF 进程内托管 ASP.NET Core 局域网服务，共用当前冻结剧本包及本局状态。图片从私有资产目录按明确索引提供，公共对话使用独立投影。Blazor Interactive Server 是技术候选，须先通过真实平板浏览器验证（不限定浏览器品牌，见第 3 节）。

**Tech Stack:** 既有 .NET 10、WPF、SQLite；新增 ASP.NET Core 服务端网页。PDF 渲染优先验证 Windows.Data.Pdf；二维码生成依赖在实施时核实许可并锁定版本。

## 1. 本轮已确认的范围

用户最后明确：**“不需要知道能不能翻 所有的卡按照名称列出来 玩家点击哪个推送哪个”**。本决定覆盖交接文档 8.2 中的防提前发卡要求，以及 8.3 的环节分配、三种状态和前提确认设计。

| 项目 | 一期行为 |
|---|---|
| 卡片目录 | 全部线索卡名称从加入后就可见，可搜索，按来源分组和卡号排列 |
| 卡片访问 | 点击哪张，服务端就向发起点击的平板提供哪张卡面；当前环节不参与判断 |
| 名称与文件 | 提前提取、确认卡片名称，建立名称到单卡文件的索引；同名时显示分组和编号区分 |
| 拆分失败 | 暂停该组分发，明确显示未准备好；不以整页代替单张 |
| 技术选择 | 先验证 Blazor Server，在真实平板浏览器（不限定品牌）通过后才定型 |

“推送”在一期指点击后的取图响应，图片显示在点击者平板。不强制让其他平板弹窗或自动打开同一张卡；其他玩家可以从同一完整列表自行打开。不存在卡片首次开放、领取独占、领取次数或按环节锁定的状态。

这意味着玩家可以提前打开任何已准备好的线索卡，何时点击由玩家遵循规则。软件仍要保证点选与图片一一对应，避免取错卡、正背面配错或露出邻卡。电脑推进、投票和揭秘继续走原有业务规则，不因浏览线索卡而推进或改变。

一期保留纸质模式，新增平板模式。整本角色本按认领角色提供，支持翻页、双指缩放、横竖屏。公共对话和当前环节只读，平板没有聊天输入、推进或揭秘按钮。

个人回忆卡包、抉择卡包、投票和私聊不在一期。若某张此类卡已作为线索卡导入，一期仍属于完整名称列表，不额外实现个人归属或关键词触发。角色本以后按环节解锁属于后续功能。

## 3. 先过技术验证，再接入正式导入

比较过三条路线：Blazor Interactive Server 便于沿用 C#，但依赖连接恢复；简单 HTML 加 HTTP 接口对持续连接依赖较小，但要另写前端状态同步；WASM 增加客户端运行时和共享契约，一期不选。按用户决定先验证第一条，失败时交付实测证据再修订技术选择，不能自行跳过门槛。

实施者先用合成图片、合成角色和合成对话搭最小探针，证明从 WPF 同进程启动和停止服务，网页在目标设备可用。不得拿真实角色本截图作演示证据。

| 实测动作 | 通过条件 |
|---|---|
| iPad 和安卓平板各用一台真实设备、各自设备上可用的浏览器扫码加入（不限定品牌，不装 App） | 能选角色，能打开正确图片，没有本机证书安装步骤 |
| 6 个浏览器会话同时打开不同卡、翻角色本 | 各自取得对应图片，页码不会串到其他客户端，WPF 仍能操作 |
| 平板双指缩放，横竖屏切换 | 可放大阅读并回到目录，不禁用浏览器原生缩放 |
| 锁屏 60 秒、切后台 60 秒、Wi-Fi 断开 30 秒后回来 | 显示断线状态；连接可恢复或提供明确刷新入口。刷新后回到本局和本人角色，不自动重发电脑操作 |
| 停止服务、切换剧本、重启 WPF | 旧页面不再读取旧局资产；重新加入正确局。旧请求不能误取新局同号卡 |

将设备型号、系统及浏览器版本、动作、实际结果写入 `docs/evidence/tablet/browser-spike.md`。本轮未连接真实平板，此表当前全部未执行；实施阶段先交这份证据，再决定是否进入正式网页建设。单用桌面浏览器或模拟器不算真实平板验收。设备试验按用户最新决定不限定 Safari：iPad 与安卓平板各选一台，用其自带或可用的浏览器实测；某款浏览器不兼容时在同一设备上换一款再测，并如实记录版本与结果。

官方文档说明服务端 Blazor 通过 SignalR 与浏览器交互，连接配置需单独考虑，见 [Blazor SignalR 指南](https://learn.microsoft.com/en-us/aspnet/core/blazor/fundamentals/signalr?view=aspnetcore-10.0)。业务状态不能只放在浏览器连接对应的 circuit 中，刷新应能重新建立页面。

局域网一期先用 HTTP 和本地 IP，不要求安装证书。不能承诺网页让屏幕常亮：Screen Wake Lock 要求安全上下文，见 [MDN 文档](https://developer.mozilla.org/en-US/docs/Web/API/Screen_Wake_Lock_API)。加入页提示玩家在系统设置中调整自动锁定；断线恢复仍必须验证。

## 4. 导入与命名

保持现有五步向导，在识别完成后、最终建包前增加“平板材料准备”区，不另建一套导入流程。电脑默认只显示公开名称、编号、数量、来源页号和准备状态。角色本正文、卡面、主持手册和真相仍不在导入界面展示。

### 4.1 每张卡建立固定索引

每张卡有稳定 `cardId`、`displayName`、`groupName`、`sourceOrder`、`frontAssetId`，以及可选的 `backAssetId`。名称是玩家定位入口，实际取图使用 `cardId` 和冻结资产索引，避免同名、重命名、特殊路径字符造成错图。

命名优先读取卡背已有名称，其次读取卡面明确印刷的标题或卡号，不让模型从正文概括剧情式名称。来源文件名已有清楚名称时沿用；名称只有数字时结合公开分组名显示。仍缺名称的卡显示来源编号并标“待命名”，在准备区编辑后才供平板分发。

用户说的“提前命名好”由导入准备完成，不要求玩家先读卡面。派生单卡文件可用稳定编号命名，清单负责保存可读名称及其来源；不重命名或覆盖原始资料。保留原文件名作为查找别名。同名卡的列表项显示分组和编号，禁止模糊搜索命中后自动取第一张。

名称本身来自卡片的标题，玩家接受从一开始看到全部名称；不要为了命名生成尚未在标题中出现的剧情摘要。OCR 不能确认名称时保持待处理，不编造。卡片名与正背面配对是两项独立校验。

### 4.2 单卡配对与整版切图

单卡文件按文件名、编号和正背面标记提出配对候选。在准备区显示两个文件引用和数量，让人确认；不能把样本中的特殊别名写成全局规则。冲突、缺正面或不明确的配对使该组无法分发，允许改配对。

整版使用通用网格参数：行数、列数、有效区域、有效槽位，以及正背面槽位映射。先归一化图像方向；“5 行 1 列占左半页”要设置左半有效区域，不能把整幅宽度当成单卡宽度。每个边界按整图位置独立取整，避免逐行累积误差。正背面尺寸不同时分别映射各自的有效区域。

默认提出同槽位对应，允许水平反转映射，但两种都不是对新剧本的事实保证。记录原文件 hash、页号、有效区域、网格、槽位和映射，能回溯每一张派生单卡。

合成图测试必须包含每槽不同标记、四边标记、空槽和非整数行高，确认无邻卡、无漏边、正背面一一匹配。真实材料需由用户明确授权的独立校验者在私有位置核验全部产物，仓库只记录数量和结论；不能要求本局玩家提前看卡面。无法确认质量的组保持未准备好，正常玩纸质模式或换材料，不能把整页发出去。

该组暂停只影响该组数字材料，不阻止角色本和其他准备好的组使用。平板模式开局前明确列出未准备好的组，避免玩家到现场才发现缺卡。导入取消只清理本次产生的未发布临时资产，成功后原子发布清单与文件。

### 4.3 角色本图片化

图片角色本按确认过的页序复制到私有资产目录，保留原图。PDF 优先试验 Windows 原生 `Windows.Data.Pdf.PdfDocument`，使用解析器的 `PageCount` 和逐页渲染接口，见 [官方 API](https://learn.microsoft.com/en-us/uwp/api/windows.data.pdf.pdfdocument?view=winrt-26100)。实施时确认 Windows SDK 目标、.NET 调用和实际发布物，不能把 PyMuPDF 的试验成绩当成这条路线已通过。

先用 150 DPI 导出，真实平板试读后决定是否提高分辨率，渲染参数进入资产指纹。正文不清晰不能仅靠调高 JPEG 压缩率凑目标体积。页数不采用现有 `CountPdfPages` 的字符串计数作最终依据。密码保护、损坏或页数失配应明确失败，不少页交付。

PyMuPDF 留作已观察到可行的候选，不直接加入分发依赖；若原生路线受阻，先报告原因、依赖及许可核查结果，再修订。角色本渲染是本机图片处理，不新增向主持模型发送角色本的路径。

## 5. 数据边界与网页契约

### 5.1 冻结资产，不改旧局

在冻结包中新增可选的平板清单，旧包缺少清单时继续支持纸质模式，界面提示重新准备后才能使用平板。新增清单与资产内容 hash 纳入 `ContentHash`，沿用 `ScriptPackage.Identity` 绑定本局。变更名称、切图或角色页序都生成新包版本，不覆盖旧局资产。

资产目录以包内容指纹隔离。资产清单记录 `assetId`、内部相对路径、内容 hash、类型、来源文件及页槽信息。角色页清单按 `roleId` 保存有序的 `assetId` 列表。客户端不会收到物理路径、SourceSpan 原文、完整 ScriptPackage、组织者手册或真相对象。

图片按页、按卡加载，通过 HTTP 图片响应传输，不把图片 Base64 塞入 Blazor 连接消息，不一次下载全部角色本或全部卡面。准备好的所有卡在业务上均可访问，按需传输是为了明确选择和节省流量。

### 5.2 会话与取图

| 入口 | 输入与输出 | 校验 |
|---|---|---|
| `POST /tablet/join` | 二维码中的本次服务加入令牌，换成本局浏览器会话 Cookie | 服务已启用，令牌仍属于当前局 |
| `POST /tablet/role` | `roleId`，返回本人角色和页数 | 角色存在；同时认领冲突返回 409，页面刷新角色列表 |
| `GET /tablet/catalog` | 返回全部卡片 ID、公开名称、分组、编号和准备状态 | 本局会话有效，不包含卡面或卡面缩略图 |
| `GET /tablet/cards/{cardId}/front` | 对应单张卡图片 | 当前冻结清单中存在且该组已准备好；不检查环节 |
| `GET /tablet/role/pages/{pageNumber}` | 本人角色对应页图片 | 从 Cookie 的角色解析；客户端不能传别人的角色或任意文件路径 |

另设 `GET /tablet/public?after={sequence}`，返回当前环节、公开消息及下一序号。图片错误码约定：会话无效 401，未认领角色访问角色本 403，ID 或页号不存在 404，组未准备好 409。UI 显示可理解的提示，不显示异常堆栈和私有路径。已认领角色可以主动退出后重新选择，不做设备绑定、账号或电脑审批。

Blazor 页面在服务端调用同一查询服务，图片仍走上述 HTTP 接口。浏览器 Cookie 防止意外串角色，写接口做同源及防伪校验，不额外建设账户系统。停止服务、切换本局或重启后作废旧加入令牌和浏览器会话；新二维码重新认领。普通网页刷新保持当前有效会话。

HTTP 服务默认关闭，电脑点击“开启平板分发”才绑定所选局域网 IPv4 和端口，二维码在本机生成。端口占用或地址不可用时报告原因；电脑界面可更换端口和网卡。禁用目录浏览，不开放任意文件下载，不监听公网地址，不配路由器端口转发。防火墙指引仅针对当前应用的专用网络，不自动关闭防火墙。

本模式面向同一局域网内的朋友，提供防误看，不承诺抵御同网段恶意用户。电脑的手册、设置、模型密钥和存档不属于任何网页下载入口。

### 5.3 公共对话投影

`HostViewModel.AddMessage` 已有 `MessageAppended` 事件，接入此公共显示出口和已提交的环节变化。同步玩家公共发言、已落在电脑公共聊天区的主持回复和公开流程事件，过滤本机诊断。公共消息带本局 ID、单调序号、作者和正文，浏览器按序号去重。

不能把 `DmConversationSnapshot` 发给平板，它含备忘，且旧轮次会压缩。为平板建立单独的公开消息记录，由同一个 `SessionStore` 写入 SQLite，和模型记忆分别保存。平板加入、刷新和恢复后按本局读取这些公开消息；升级前未保存的历史不从 AI 备忘重建。

网页线程不能枚举 WPF 的 `ObservableCollection`。在 UI 消息出口复制成不可变公共消息，提交后通知网页。公开消息保存失败时显示同步异常、停止继续累加会造成缺口的同步，提供重试，不能报告已同步。不同局的序号和缓存隔离。公开消息恢复不触发 TTS；翻卡和浏览角色本不自动写入公共对话、AI 历史或游戏事件。

## 7. 验收合同

自动化使用合成数据，新增 `tests/LocalDm.Tests/TabletAssetTests.cs`、`TabletQueryTests.cs`、`TabletHttpTests.cs`、`TabletPublicFeedTests.cs` 和 `tests/LocalDm.UiTests/TabletImportTests.cs`、`TabletHostTests.cs`。HTTP 测试须实际启动服务、发请求并断言响应，不能只测试内部方法。

| 场景 | 必须观察到的结果 |
|---|---|
| 当前仍在首环节，目录中选来源标为后续环节的卡 | 名称存在且取图成功，返回该张卡合成标记，不改变本局 revision、阶段或 AI 历史 |
| 同名卡两张、搜索、改显示名 | 各自 ID 稳定且返回不同的正确图片；不靠名称拼文件路径 |
| 5×2、左半区 5×1、反转映射、边长不能整除 | 每张四边和槽位标记完整，无邻卡；正背面对应预期文字标记 |
| 拆分质量未确认或组资产缺失 | 该组请求 409，目录明确不可用，不返回整版；其他组继续成功 |
| 角色页请求、失效会话、路径穿越、猜测资产 | 只给本人角色页；其他文件、手册、真相和磁盘路径均取不到 |

另覆盖公开消息去重及补发、保存失败、备忘不进入同步、切局失效、认领并发冲突、停止和重启生命周期。取图应按实际图片标记断言，不能只断言状态码 200。

真实材料验收按用户单独授权，在私有位置核对完整卡数、全部正背面映射、边缘及角色页序；仓库仅记结构与结果。第 3 节设备试验和实际发布物验收不能被单元测试替代。完成这些后仍需真人整局试玩，不能仅凭构建通过声称整局可玩。
