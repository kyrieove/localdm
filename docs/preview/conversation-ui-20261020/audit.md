# 本局主持：对话式界面审查与预览

2026-10-20，第二版。范围为当前工作区的 WPF 界面和功能入口。交付物是可点击 HTML 原型；不修改 WPF、不调用模型、不播放语音、不读写真实存档。页面内所有消息、材料编号与交互反馈均为演示。

## 审查结论

当前主窗口有 216 px 左侧导航，主持台内部又分为主栏与 392 px 右栏。环节标题、阶段轨道、操作条、常驻活动条、日志、输入区、右侧条件与动作同时占据屏幕。结果是对话区域受挤压，信息重复，许多当前不可用的按钮长期显示。

用户指定的方向是 Codex / Claude 式对话布局。预览采用 278 px 左侧控制栏，其余全部作为可切换的主内容区。沿用米白、墨色和少量印章红，减少厚边框与分隔面板。对话按时间顺序展示玩家输入、AI 回复和简短阶段事件；输入框固定在底部。真相公开后用主区宽幅展示，不再挤到侧栏。

## 功能取舍

| 当前入口或信息 | 预期处理 | 必须保留的能力 |
| --- | --- | --- |
| 首页 / 本局、主持台两套入口 | 合并为当前会话，左上保留剧本库 | 选择剧本、恢复未完成的一局 |
| 当前环节、顶部阶段轨道、右栏本环节 | 集中到左侧一套进度轨道 | 当前阶段与前后顺序可辨认，不允许任意跳转 |
| 原本条件 | 左侧紧邻推进按钮 | 无剧透条件可见 |
| 大家已准备好 | 删除勾选，点击动作本身表示决定推进 | 当前提示仍可见；机器可检查的条件仍校验，不重复询问人是否准备好 |
| 开始这一局 | 只在 Prepared 显示 | 剧本 Ready、全员准备与纸笔汇总默认方式须在真实开局流程明确接受 |
| 下一环节 | 从剧本下一步骤生成名称，例如「进入第二轮搜证」 | 规则核心校验，不让模型或自然语言直接改状态；不固定七个阶段 |
| 发放一个材料编号 | 有可发材料时显示 | 逐个发放、记录已公开编号；不显示未公开材料内容 |
| 投票输入 / 提交汇总 | 剧本有投票时才提供入口，集中录入 | 非负整数、总数等于人数；点击「确认提交汇总」即确认，不再打勾 |
| 揭秘 | 仅当前步骤需要时显示「公开真相」或剧本定义的动作名 | 按钮旁明确说明点击将公开结局；点击即确认，不再打勾或重复弹窗 |
| 进入复盘 | 真相公开后显示 | 宽幅查看已公开原文和时间线 |
| 暂停并保存 / 继续 | 一个随状态切换的按钮 | 恢复原阶段、保留已解锁真相；停止语音与暂停游戏是不同操作 |
| 公共开场 | 开场时提供快捷意图 | 按当前剧本生成口播，不等于开局或推进 |
| 停止 | 生成或播放中才出现 | 同时取消当前请求 / 播音，丢弃晚到结果；不回滚游戏状态 |
| 重播 | 放到每条主持回复旁 | 复用保存文字，不再请求模型，不重复提交状态 |
| 主持记录 / 实时互动分区 | 合并为连续对话 | 玩家原话、主持回复、阶段事件有明确归属 |
| 常驻“就绪”整块状态栏 | 移除空闲占位，保留就地反馈 | 生成、朗读、取消、失败时明确显示状态 |
| 主持台装载演示剧本 | 从主持台移除，放回剧本库 | 首次使用可体验合成剧本 |
| 音色选择、试听、重新检测 | 左下声音入口；设置内处理 | 播音失败保留文字，试听与实际回复共享语音能力 |
| caller key 输入与加密保存 | 删除日常可见控件 | 网关可选鉴权、既有密钥读取和 DPAPI 存储仍保留，不因 UI 精简破坏连接 |
| 模型地址、model ID、读取列表 | 普通设置显示模型名；高级设置处理连接 | 实际可用模型与本机地址约束；连接异常可恢复 |
| MinerU 路径 / 文档工具说明 | 移出游玩界面 | 属于剧本准备工具的配置；游玩只读准备好的剧本包 |
| revision、回执、工具错误细节 | 不上公共屏，留在内部诊断 | 去重、并发版本校验与事务持久化 |

## 原型覆盖与待实现差异

原型包含两套配置：七步的单轮搜证、有投票流程；六步的双轮搜证、无投票流程。阶段、提示、下一步名称、材料编号、投票与结局动作均从当前配置渲染，不按固定阶段序号判断。双轮示例的搜证步骤要求材料发放完成后才能继续，用来展示机器条件与人为确认的区别；这不是对真实剧本规则的推断。

顶部的流程示例、步骤切换与“按钮审查”仅用于设计评审，不属于正式产品。这两套配置均为显式编写的原型数据，不代表现有系统已经能自动解析不同剧本流程。聊天请求推进只给出操作说明，阶段保持不变。推进、提交票数和公开结局都以对应按钮点击为确认，不再额外勾选。

原型中的“自动朗读”开关、逐消息重播、设置立即应用和连续保存玩家消息，是拟议交互，不能据此认为现有桌面程序已经提供。设备输出展示为“跟随 Windows”，没有虚构应用内音频设备选择能力。

正式实现需要同步调整剧本准备器、动作数据和命令确认契约，再接入规则核心和会话存储。当前 RealScriptPackageBuilder.BuildPhases 仍生成固定七步，现有 GroupReady 与 Confirmed 检查也仍存在，不能仅删除控件后让命令持续被拒绝。原型的浏览器内状态逻辑仅用来验证界面，不应迁移为业务规则。进入复盘与结束状态需要映射到实际 GameEngine.Complete；模型失败和语音失败需要分别显示，不能把模拟成功当成运行成功。
