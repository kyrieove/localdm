# 0003 主持模型读组织者手册与线索卡，不读角色本

日期 2026-10-20。状态为已实现并通过自动化验证；人工试玩验收见方案第 5 节，尚待执行。
**已被 [ADR 0011](0011-dm-reads-whole-script.md) 取代（2026-10-25）：角色本现在也给主持模型。**

## 背景

真人 DM 在开局前会把组织者手册从头读到尾：规则、发放时机、真相都心里有数，
再把线索卡按编号整理好发给玩家。角色本始终在玩家手里，DM 也不需要看——
看了反而容易在桌上说漏。

上一版实现把整本剧本（含角色本）交给主持模型。这对「让 DM 知道全貌」省事，
但和现场形态对不上：AI 说的话全桌都听得到，而角色本里的东西玩家从没公开过。

## 决定

主持模型作为 DM，开局就读完组织者手册（含真相与主持人专用页）与全部线索卡
正反面；角色本任何时候都不给，揭秘后也不给。依据是
`docs/plans/2026-10-20-ai-dm-organizer-context.md` 第 1 节。

- 隔离发生在**上下文构造处**：按剧本包里已有的事实判定（角色的来源 span、
  材料的来源 span），不靠目录名或段 ID 猜，也不靠提示词让模型自己不看。
- 组织者手册与线索卡因此进入固定提示词之后的主持资料；system 整局不变，
  当前局面、真相状态与 model ID 放最后一条 user 消息，前缀缓存能一直命中。
- 防剧透由主持提示词第 5、6 条与【当前局面】的「真相状态」承担：未揭秘时
  不得说出或暗示真相、凶手、作案手法与任何角色的隐藏身份。
- 真相对外公开仍然只有一个开关：操作者点「公开真相」。

## 代价

防剧透从「程序保证」退到「提示词加人工验收」：模型有可能在边缘情形说出不该说的内容，
而软件按产品决定不审查模型输出（回什么念什么）。因此：

- 公共投影、UI、日志与朗读仍按原来的硬规则隔离；
- 角色本在上下文构造处硬隔离，未揭秘时不把真相交给模型；
- 人工试玩验收成为防剧透的最终关口，不合格时调整提示词措辞，不加关键词过滤。

## 验证方式

见方案第 5 节：用《孽岛疑云》真实剧本包配置 DeepSeek，跑 13 条对话，
只记录 AI 的回复是否合格，不贴剧本原文。其中第 6 项（「谁是凶手」「是不是同一个人」）
不合格就调整提示词第 5 条的措辞再试。
