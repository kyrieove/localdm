# 0009 平板「组织者手册」页签：已认领角色的会话可翻手册原稿页

日期 2026-10-23。状态：已实现，单元与接口测试通过；真实 iPad 与安卓平板实测未做。本文件不含剧本正文、卡面或真相。

## 背景
AI 主持表现不好时，桌上的人要能自己翻组织者手册接着玩。手册在电脑里，平板上看不到。ADR 0005 与平板分发契约原来写明「手册、真相不进入平板接口」。

## 决定（用户逐条确认）
1. 平板现有页签旁加「组织者手册」页签，只有已认领角色的平板看得到。不做 PIN，不加组织者身份，不做「含真相，确认要看吗」的防误触确认：用户说明大家懂规则，只看流程，不会多看。
2. 手册页接口 `GET /tablet/handbook/source/{页}` 和角色本原稿页一样要求已认领角色；没有会话、没认领角色、页号越界都返回 404。
3. 一页一页看原稿页（PDF 渲染成图，图片原样），只读，没有文字重排，不记阅读进度。复用角色本阅读器，加原稿地址前缀与「只看原稿」两个参数。
4. 手册整份逐页给出，包括真相页和声明「不入包」的页。哪个文件是手册按剧本包里已有的事实判断：文件里有来源 span，且没有一个 span 属于角色本或线索卡（与 `HostNarration.IsRoleBookSegment` 同源，不按目录名或段 ID 猜）。混了角色页的文件一律不算手册。
5. 手册页作为新的平板资产种类 `HandbookPage` 在平板准备时生成，清单版本升到 3，旧包打开时自动重新准备。

## 否掉的方案
- 组织者 PIN（4 位或 6 位加锁）：用户认为不必要。
- 只在电脑本机浏览器看手册：满足不了「用平板接着看」。
- 手册文字重排：违反「平板放原稿页不放文字」的决定。

## 后果
- 宪章原则 II 的平板边界变为：手册原稿页只经已认领会话的手册接口提供，仍不进入公共消息投影与卡目录。防泄露测试照旧：投影里出现手册即失败。
- ADR 0005 的「手册不进入平板接口」与平板分发契约相应改写，指向本文件。
- 代价：任何认领了角色的玩家都能翻到真相页，靠玩家自觉。
- 重新验证要求：真实 iPad 与安卓平板各翻一次手册页签，记进 `docs/evidence/tablet/`；通过前不得说功能完成。
