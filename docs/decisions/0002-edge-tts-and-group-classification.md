# 0002 神经语音降级链路与角色/线索分流依据

日期 2026-10-20。状态为已实现并通过自动化验证。

## 背景

2026-10-20 的一轮代码审查（`docs/reviews/2026-10-20-code-review.md`）暴露了两处
「事实被丢掉、只能靠猜」的问题，两者都会破坏产品的核心承诺。

## 决定一：神经语音是可选增强，永远不是前提

主持口播的主引擎是 Windows System.Speech（离线、随系统）。微软 Edge-TTS 神经音色
（zh-CN-YunxiNeural 等）通过本机 python + edge-tts 作为**可选增强**接入。

- 三条硬约束写进 `EdgeTtsEngine`：
  1. 不写死任何开发机绝对路径（脚本随输出目录走，解释器只认 `LOCALDM_PYTHON_PATH` 或 PATH）；
  2. 子进程的 stdout/stderr 必须被读走，管道写满会让子进程永久阻塞；
  3. 播音必须有硬超时，网络卡住不许把播音队列堵死。
- 探测结果只认「python 能 import edge_tts / soundfile / sounddevice」，并带 5 分钟缓存，
  超时必杀子进程，不留孤儿进程。
- 口播文本经 stdin 传给脚本，不进命令行：命令行有长度上限，且任务管理器能直接看到参数。
- 引擎抽成 `IEdgeTtsEngine` 契约，使「Edge 不可用时降级到本地 SAPI」这条路径
  能在没有 python、没有网络的机器上被真正测到。
- 降级必须是静音的正确性：本地回退只从中文音色里选，绝不退到英文音色去念中文剧本。

## 决定二：角色本/线索卡的分流采信导入源头的事实

角色本与线索卡牌在导入源头本来就是分开的目录（`BuildPackageProbe` 单独收集
`roleDir` 与 `clueDir`）。这个事实此前被丢掉，只剩目录名，靠 `IsMaterialGroup`
的子串启发式猜（`-`、`楼`、`室`、`现场`、`抉择`、`回忆`、`线索`）。

误判方向都有害：

- 角色本被当成线索卡堆 → 该角色从 `Roles` 消失，其**分组名被写进公共材料编号**，
  主持人一旦「发放」，私有角色本的编号就进入公共投影与模型上下文；
- 线索卡被当成角色本 → 搜证阶段一个编号都没有，主持台看起来像坏了。

因此 `ExtractedPage` 增加 `GroupKind`（Role / Material / Unknown），导入源头标注的事实
是唯一依据，目录名启发式降级为兜底（`ResolveGroupKind`）。

## 影响与重新验证

- 秘密隔离的判定收口为 `TruthAccess.IsUnlocked`，并把「暂停且 ResumeState=Revealed」
  计入已解锁：引擎的 `Complete` 早已这样认定，口播依据若不认，主持人一按暂停真相就消失。
- 允许手动发放的阶段：进入时不再整批并入材料（逐个发牌按钮全程灰显的老问题），
  但**离开该阶段时补齐未发放的编号** —— 主持人跳过环节时线索不许永久丢失。
- 复核要求：见 `docs/reviews/2026-10-20-code-review.md` 的「重新验证」一节。
