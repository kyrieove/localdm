# 0006 软件内置语音输入：本机录音 + 本机识别

日期 2026-10-23。状态：已决定，已实现（引擎卡 `docs/orch/2026-10-23-dictation-engine/`、界面卡 `docs/orch/2026-10-23-dictation-ui/`），真人麦克风实机验收未做。

## 背景
原约定（`PRODUCT.md`、`docs/user-guide.md`）：语音输入走用户已有的 OpenLess，软件只收文字、不碰麦克风。用户提出在主持台输入框加语音按钮，按了就语音转文字。调查事实：OpenLess 2.0.1 没有任何对外接口（无 API、无命名管道、无转写命令行），只能靠全局热键把字打进当前焦点窗口；它的本地识别是 sherpa-onnx + qwen3-asr-0.6b-int8，模型已在本机 `%APPDATA%\OpenLess\models\sherpa-onnx\`；它的源码是 AGPL-3.0。

## 决定（用户逐条确认）
1. 软件自己录音、自己识别，不依赖 OpenLess 是否运行；识别全在本机，口播内容不出本机。
2. 识别用 sherpa-onnx 官方 .NET 包（Apache-2.0）加载 Qwen3-ASR（模型 Apache-2.0）；**不复制 OpenLess 任何代码**，只借它的思路（16 kHz 单声道 16 位、录音时才加载模型、用完释放）。
3. 模型：第一次使用时把 OpenLess 已下载的 qwen3-asr-0.6b-int8（约 0.9 GB）复制到软件数据目录并校验 SHA-256；不直接读 OpenLess 目录。找不到时明说，不静默失败。
4. 操作：输入框右侧麦克风图标，点一下开始、再点一下结束；快捷键右 Alt，只在本软件窗口在最前面时生效（不装全局键盘钩子）；录音超过 60 秒自动结束。
5. 转出的文字填进输入框，不自动发送；点语音按钮时先停掉当前朗读；不区分说话人。
6. 模型启动时不加载，第一次点麦克风才加载，识别后闲置 5 分钟释放。
7. 提示：模型未备好就开始准备并显示进度；没有麦克风或没权限、识别为空、识别出错各给一句明确的话；已转出的文字不丢。
8. 「软件不碰麦克风」旧约定作废，改为：只在点按钮后录音、音频只在内存里、识别完即丢、界面有明显的「正在听」。OpenLess 仍可照常用（文本框拿焦点后按它的热键），两者不冲突。

## 否掉的方案
- 模拟按右 Ctrl 触发 OpenLess：它是「按一下开始/再按一下结束」，软件拿不到结束信号，不可靠，且违反原约定。
- Windows 自带中文识别（System.Speech）：准确率一般，只适合短句。
- 直接读 OpenLess 模型目录：它一更新或卸载就坏。
- 拷 OpenLess 代码：AGPL-3.0 传染。

## 后果
需要同步改 `PRODUCT.md`、`docs/user-guide.md`、宪章版本号、第三方许可说明（sherpa-onnx、NAudio、Qwen3-ASR 模型）；新增 NuGet 依赖会让安装包变大。识别速度与准确率要用 `--dictation-check` 实测后写进证据文档，不凭印象。
