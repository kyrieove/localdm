# 0008 平板界面镜像：只投影公开内容，网页重做一份软件界面

日期 2026-10-23。状态：设计已由用户逐条确认（见 [设计](../plans/2026-10-23-tablet-live-chat.md) 第二期），尚未实现，真实 iPad 与安卓平板实测未做。本文件不含剧本正文、卡面或真相。

## 背景
ADR 0007 让平板能发言，但平板上仍看不到软件里的环节进度和对话全貌。用户要平板上看到和软件一致的界面。第一期（发言）本身还没有真实平板实测记录，本期不因此停下，但两期都要在真实设备上验过才算完成。

## 决定（用户逐条确认）
1. **不推送电脑屏幕画面。** 操作者随时可能打开设置页、导入向导、材料面板，推屏会把真相或备忘露给全桌。秘密在业务投影处隔离，不靠网页隐藏。
2. 在 `PublicSessionProjector` 这一路新增「平板界面投影」，只含公开内容：当前环节、环节列表、按钮可用状态、公开对话（已揭秘后的公开揭秘文本沿用现有公共投影的规则）。投影的输入类型里没有真相、备忘、上下文占用、角色本、手册，类型上就构不出它们。
3. 网页重做一份软件界面，布局和内容与软件一致，数据只取自上面的投影，实时刷新。
4. 主窗口左侧栏的「开始、推进、放出材料、提交投票、揭秘、结束、暂停/继续」在平板上显示成灰色，旁边写「请在电脑上操作」；竖屏放不下时折叠成一行当前环节。
5. 备忘、上下文占用等内部状态不显示。
6. 平板上能点的仍只有「发送」和「停止朗读」。发言继续走第一期的 `TabletSpeechService` 和 `HostViewModel.SubmitTabletSpeech`，不另写发送逻辑。
7. 刷新或掉线后用已有的按序号补拉（`GET /tablet/public?after=N`）恢复对话，不丢。

## 否掉的方案
- 推送电脑屏幕画面或截图：见决定 1，秘密靠“当时没打开那个页面”才不露，不可接受。
- 网页拿完整会话数据再自己隐藏秘密：违反宪章原则 II，隐藏不是隔离。
- 平板上让灰色按钮可点、点了再提示去电脑：违反宪章原则 III，也和 ADR 0007 第 9 条“能点的只有发送和停止朗读”冲突。

## 后果
- 宪章升为 8.0.0：平板由“只能发言”变为“同步显示整套公开界面”，原则 II（秘密隔离）的投影边界和原则 IV 的设备边界扩大。重新验证要求：防泄露测试（真相、备忘、上下文占用、角色本、手册任何一项出现在投影里都算失败）；用真实 iPad 和安卓平板各实测一次整套界面，记录设备型号、系统、浏览器版本和结果；通过前不得说功能完成。
- 实施拆为三张卡，后一张依赖前一张验收：①平板界面投影加防泄露测试（`src/LocalDm.Core`，高风险）；②把投影接进平板服务的实时接口；③网页界面。
- 需同步改 `specs/001-local-dm-mvp/`（FR-021、contracts、plan）、`docs/user-guide.md`、`PRODUCT.md`；ADR 0005、0007 加指向本文件的说明。
- 与 ADR 0007 第 9 条的关系：灰色占位按钮是显示，不可点，不增加平板的操作入口。
