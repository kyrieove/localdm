# 真实剧本上平板：孽岛疑云（2026-10-22）

用户要求：网站测试除了合成材料，还要用真实剧本《孽岛疑云》走一遍，
看能不能正常打开、拿到剧本（角色本）与线索卡。

本文件只记结构、数字与结论。**不含任何剧本正文、卡面文字或真相。**

关键结构结论：**每一张线索卡独占一个图片文件**（例如 `51.jpg` 与 `51卡背.jpg`），
所以这本剧本不需要整版切图 —— 资产就是原图本身。
（K7 那种一版多卡的仍要走网格切图。）

## 准备：给冻结包补平板清单

```
dotnet run --project tools/LocalDm.Probe -- --prepare-tablet \
  --package <包.json>
```

这条命令做三件事：

1. 按文件名里的编号配正反面（通用规则，不认任何剧本专属别名）；
2. 把每个卡面复制成冻结资产，资产目录按内容指纹隔离；
3. 写出一个**新版本**的包（新包标识 + 新内容指纹），旧包留在原处走纸质模式。

本次结果（孽岛疑云）：

| 项 | 值 |
|---|---|
| 新包标识 / 版本 | `pkg-14761fe2c052` / 2 |
| 卡 | 53 张进入清单 |
| 分组 | 10 个，其中 **9 个整组可用**，1 个不可用 |
| 资产 | 106 个（53 正 + 53 背） |

不可用的那一组是「回忆唐11-15」：组里有 1 张卡正反面配不唯一，按既定规则
**整组保持未准备好**，不拿整页图顶替，也不把这张混进别的组发出去。
这正是「裁不准就暂停该组」那条决定要的行为。

服务用 `LOCALDM_TABLET_PACKAGE` 指向上面准备好的包，发布版运行（Debug 版没有
`blazor.web.js`，页面不会渲染）。

| 原稿第 1 页 | 200，`image/jpeg`，722 KB，JPEG 头 `FFD8` |
| 公开消息 | 200 |

浏览器实测（内置浏览器，发布版服务）：

- 页面渲染出「加入本局」与 5 个真实角色，全部「可认领」；
- 合成材料模式同样渲染正常 —— 两者走同一个页面，只换内容来源。

未验证：内置浏览器的 DOM 查询读不到 Blazor 渲染出来的内容（截图能看到，
`inspect`/`query` 返回空），所以**点角色、点卡这两步没有在浏览器里点过**；
同样的两步用 HTTP 验过（认领 200 → 角色本 200 → 卡面 200）。

## 仍然没做的

- **服务还没接进 WPF**：现在要手工用环境变量指包，电脑上的开关、二维码、
  防火墙指引都还没有（方案第三步）。
- **真实平板（iPad / 安卓）未验收**：需要用户自己的设备。
- **导入向导里的准备区未做**：清单准备目前只有命令行这一条路（方案第二步里
  「导入向导增加准备区和分组失败说明」仍未做）。
- **一台设备的浏览器只验了桌面内置浏览器**：真正的手机浏览器还没碰过。
