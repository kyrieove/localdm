## 准备：给冻结包补平板清单

```
dotnet run --project tools/LocalDm.Probe -- --prepare-tablet \
  --package <包.json>
```

这条命令做三件事：

1. 按文件名里的编号配正反面（通用规则，不认任何剧本专属别名）；
2. 核对每个源文件的 SHA-256 与包里记录的是否一致 —— 对不上说明材料被换过，
   那一组不分发；
3. 把每个卡面复制成冻结资产（资产目录按内容指纹隔离），
   写出一个**新版本**的包（新包标识 + 新内容指纹），旧包留在原处走纸质模式。

### 公开消息这一项为什么是空的

独立运行的平板服务**看不到桌面那一局的对话存档**（存档在 WPF 那一侧，
服务还没接进 WPF）。所以包模式下公开对话是空的，页面明说
「还没有公开消息：电脑那边还没把这一局的对话接过来」，
**不拿合成对话冒充真实本局**。

已经打通的与还没打通的分清楚：

| 环节 | 状态 |
|---|---|
| 桌面出口 → `public_messages` 表 | 已打通并有测试 |
| `GET /tablet/public?after=N` 的契约（401/400/按序号补发/下一序号） | 已打通并有测试（真起服务发请求） |
| 服务读**真实存档**里的公开消息 | **未打通**：服务还没接进 WPF，包模式下给的是空的一段 |
| 页面读公开消息来源 | 已改成真读来源（不再写死三条合成文字） |

## 仍然没做的

- **服务还没接进 WPF**：现在要手工用环境变量指包，电脑上的开关、二维码、
  防火墙指引都还没有（方案第三步）。
- **公开消息的最后一跳**：服务要拿到桌面那一局的存档来源（第三步一起做）。
- **真实平板（iPad / 安卓）未验收**：需要用户自己的设备。
- **导入向导里的准备区未做**：清单准备目前只有命令行这一条路（方案第二步里
  「导入向导增加准备区和分组失败说明」仍未做）。
- **一台设备的浏览器只验了桌面内置浏览器**：真正的手机浏览器还没碰过。
