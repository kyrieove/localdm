### 之前四个模型为什么都不成功

| 模型 | 结果 |
|---|---|
| `workbuddy-ai/deepseek-v4.1-flash`（用户设置值） | HTTP 429，额度当时未恢复 |
| `deepseek/deepseek-flash` | 返回的 JSON 里没有 steps，判「没有给出任何环节」 |
| `deepseek/deepseek-v4-pro` | 先返回无法解析的 JSON；修好中文类别解析后再试，HTTP 402 余额不足 |
| `antigravity/gemini-3.8-flash` | 与 deepseek-flash 同一现象：返回的 JSON 里没有 steps |

**真实原因：提示词没有写 JSON 结构。** 初版提示词只说了「只输出 JSON」，没给字段名，模型就自拟了一套结构
（环节换了别的 key、`layering` 换了别的写法），而解析器只认 `steps` / `layering.truthPages`，
于是判成「没有给出任何环节」。这与请求大小无关，也不是回复被截断：两个厂商的模型返回的都是完整、
合法的 JSON，只是字段名对不上。同一份提示词补上结构说明后，同一个 `antigravity/gemini-3.8-flash`
一次就起草成功——说明当时猜的「请求太大 / 输出额度敏感」是错的，向导侧的解析、重试与兜底本来就是对的。

修复 `4b9c756`：提示词第 8 条写明完整 JSON 结构与每个字段名；新增测试钉住这 11 个字段名必须出现在提示词里；
模型漏写 `stepId` 时按顺序补成 `step-N`，不再为内部标识整份判失败。

失败兜底仍然保留：解析不通过就重试一次，仍失败才显示「AI 没能起草流程」，并给一份空白环节表，
不套默认流程。
