# 证据目录约定

本目录保存实施过程的实证记录。每份证据必须能回答「跑了什么命令、看到什么结果、哪些没验证」。

## 文件组织

```text
docs/evidence/
  README.md              本约定
  setup/                 环境与构建基线
  us1/ ... us5/          各用户故事的实测证据
  final-validation.md    quickstart 最终复核
```

## 每份证据必须包含的字段

| 字段 | 要求 |
|---|---|
| scenario | 被测场景编号（对应 spec 验收场景或 tasks ID） |
| commit | 记录时的 git commit（`git rev-parse --short HEAD`）；未提交时写「工作区未提交」 |
| command | 实际执行的命令或操作步骤（PowerShell 可直接复现） |
| result | 实际输出摘要（通过/失败/退出码），失败的原文贴入 |
| screenshot | 界面类证据的图片相对路径；无界面则写「不适用」 |
| limitations | 未验证项、受阻原因、只验证到哪一层 |

结论只能写三种：**已通过**、**未执行**、**受阻（原因）**。不写「应该可以」。

## 禁止内容

- 真实剧本正文、角色秘密、凶手、真相段落或截图中的私人材料页面。
- 供应商密钥、caller key、DPAPI 密文、MinerU 内部配置与 token。
- 用户绝对私有路径（`stories/` 下真实目录名可脱敏为 `<story>`）、录音、存档数据库内容。
- 未脱敏的工具 stderr 全文，尤其含路径或密钥的行。

## 与验收的关系

合成材料、Mock、构建通过或单测通过**不能**替代真人整局与目标机发布物验收。
未获授权的真实剧本校验、未运行的 MinerU 服务、未安装的发布包都必须如实记为未执行或受阻。
