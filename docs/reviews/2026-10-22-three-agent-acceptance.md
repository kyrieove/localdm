## 独立复现的阻断问题

以下复现调用 MiniMax 已构建的真实 Core、Infrastructure 和 Tablet 程序集，而不是在脚本中重写被测算法。只创建临时合成 PNG、角色页和两页 PDF。记录位于被忽略的 `artifacts/tablet/three-agent-review/reproductions.json`，重跑脚本为同目录 `reproduce.ps1`。源码改动后应先重建目标分支，旧 DLL 结果不能替代新提交验收。

### 1. [P1] 未确认的整版多卡图会直接成为 Ready 单卡

归属：MiniMax。位置：`src/LocalDm.Infrastructure/Import/TabletPackagePreparer.cs:48,158`。

准备器无条件把材料源文件送入 `PairSingleCards`，随后完整复制原文件。没有单卡确认、版面类型或网格参数，也不调用网格裁切。独立合成四区域图片按普通编号文件输入后，清单状态为 `Ready`，取图返回与整张输入完全相同的字节。

这条路径不是“网格功能还没做”的空白，而是会主动发布未经拆分确认的图，违反已确认的“拆分不可靠则暂停该组，不发整页”。修复需明确区分已确认单卡、已确认网格和未知材料；未知状态不能自动 Ready。

### 2. [P2] 分组名经有损净化后碰撞，两张不同卡覆盖成同一文件

归属：MiniMax 的准备落盘集成。位置：`TabletPackagePreparer.cs:103,134,260`。

两个合法合成分组 `A.B` 与 `A B` 各有编号 1 的不同图片，产生不同 cardId，但文件路径都变为 `cards/A-B-1-front.png`。实测输入字节不同，最终两个卡 ID 返回的字节相同。

应使用可追溯且不会因净化碰撞的稳定文件名，写入前校验相对路径唯一性；补充跨分组同编号、标点与空格名称的实际取图测试。

### 3. [P2] 已冻结资产被替换后，网站仍按原卡 ID 发出新内容

归属：MiniMax。位置：`src/LocalDm.Tablet/PackageTabletContent.cs:73-82`。

查询结果有 ContentHash，运行时却只判断文件存在后读取。独立复现准备清单后替换派生图片，取图仍成功、failure 为 `None`，返回替换后的字节。

应对实际读取的字节核对冻结 hash，并检查规范化路径仍位于资产根目录；错误时停止该组分发，不能用旧包身份提供新图片。

### 4. [P2] 已声明卡背校验失败被悄悄当作“本来无卡背”

归属：MiniMax。位置：`TabletPackagePreparer.cs:122-146`。

合成包先记录正背面 hash，再替换卡背后准备，结果仍为 `Ready`，BackAssetId 被删除。当前逻辑只是不加入卡背计划，没有把组标为未准备好。

必须区分来源本来没有卡背与已有卡背损坏、缺失或被替换。后者应明确暂停，不得静默改变冻结材料的组成。

### 5. [P2] 图片角色本把“文件内第 1 页”误当整本阅读页序

归属：MiniMax。位置：`PackageTabletContent.cs:140,164-174`；来源约定见 `ScriptImportService.Extract.cs:132`。

单张图片的来源文件页号本来都是 1。独立输入三张角色页后，网页模型有三章，但仅一个唯一 ChapterId，所有正文 SourcePageNumber 都是 1。后续阅读页的“查看原稿”会指向第一张图。

逻辑原稿页序应来自角色本有序来源索引，另存文件内 pageNumber；章节、块 ID 必须稳定且唯一。还应测试同页多块及来源列表排序，而不是只用伪造 1、2、3 的独立图片页号。

### 6. [P2] PDF 原稿接口返回整个 PDF，无法放进图片阅读器

归属：MiniMax。位置：`PackageTabletContent.cs:91-123,197-203` 与 `Pages/RoleReader.razor` 的原稿 img。

独立构造的两页 PDF 已用另一解析器验证为 2 页。两个原稿页请求均返回同一个 PDF 文件，字节相同，MIME 都为 `application/octet-stream`，开头为 `%PDF-1.4`。网页使用 img，因此这条原稿核对路径不可用。

需将 PDF 原稿按页准备为可解码图片资产，或实现明确的 PDF 原稿阅读路径；不能用返回文件成功冒充按页图片核对通过。

### 7. [P2] 通用镜像槽位映射默认写死两列

归属：DeepSeek；MiniMax 已带入相同实现。位置：`src/LocalDm.Core/Tablet/TabletManifest.cs:267-273`。

`DefaultForPairing(true)` 固定 BackColumns=2，且用 Math.Max 把越界结果夹为 0。三列输入 0、1、2 实际输出 1、0、0，期望为 2、1、0。两张背面被映射到同一正面。

调用时必须明确实际列数，非法槽位应被拒绝，不能通过夹值让坏映射看似有效。当前正式准备器尚未调用网格路径，但该底层能力仍不能算通用网格验收通过。

### 8. [P2] 整版水平镜像与奇数宽度组合出现邻卡像素

归属：DeepSeek；MiniMax 带入相同实现。位置：`src/LocalDm.Infrastructure/Import/GridCardCropper.cs:30,38-40`。

按“整版水平镜像”的语义，原行 `[1,1,2,2,2]` 镜像后为 `[2,2,2,1,1]`。两列裁剪后逐卡反转，实际得到 `[2,2]` 与 `[1,1,2]`，后一张混入邻卡像素。该数据由真实裁剪器运行得到。

目前 flag 只逐卡反转，不反射非整除网格边界。应明确整版镜像与单卡像素翻转的区别；支持整版镜像时需先还原整版或反射源区域边界。若该 flag 只表示单卡像素翻转，必须改清契约，并另行实现整版镜像，不能将现有单独镜像用例视为两种语义都已支持。

## Gemini 命令控制问题

### 9. [P2] 停止后可能被旧执行锁继续阻止发送

位置：`src/LocalDm.App/ViewModels/ShellViewModel.cs:67-94`、`HostViewModel.cs:135-136,1152-1168`。

源码路径确认：SendCommand 新增 `_isExecuting` 锁，只有原 Task 结束才复位；StopAsync 立即取消当前 generation、清除业务 busy 并显示就绪，但不结束仍在等待的网关 Task。若网关或 TTS 延迟响应取消，新发送会继续被旧命令锁挡住。现有 CountingGateway.Gate 不观察取消，能用于建立确定性的命令级复现。

这一项没有在本轮实际 GUI 中完整复现，不把已有绿色测试当作已证实取消可重发。修复和复测必须通过 SendCommand→StopCommand→再次 SendCommand 的真实命令入口，不能只调用 SendAsync 绕过新锁。保留旧 generation 的晚到结果隔离。
