# 2026-10-20 交互体验与界面完善（五轮自检）

对象：`本局主持`（LocalDm，WPF / .NET 10）。
起因：使用者指出一个具体的体验缺陷——**点完按钮到听见声音之间可能好几秒，这段时间屏幕上完全没有反馈**，人只会以为程序卡死。
做法：五轮自检，每轮「发现问题 → 修 → 验证」，并用真实窗口截图逐轮核对。

工具：`alibaba/open-code-review` v1.13.0（deepseek-flash），第 4 轮复查 39 个文件、67 条意见；
界面快照由 `tests/LocalDm.UiTests/HostDeskVisualTests.cs` 在真实 WPF 窗口上渲染 PNG（`artifacts/ui/`）。

## 0. 起点：问题被量化

基线勘查发现（不是猜测，是逐项核对出来的）：

| 事实 | 后果 |
| --- | --- |
| `SpeechState` 与 `Busy` 在**任何 XAML 里都没有绑定** | 忙的时候界面完全不变 |
| 全应用**没有一处动效** | 没有「正在进行」的视觉信号 |
| 状态文案只在右栏 392px 宽、12px 字号的最底部 | 1.5 米外看不见，且在滚动区里 |
| 命令结果（提交成功/被拒绝/缺确认）藏在右栏滚动区底部 | 主持人不知道自己点的操作成没成 |

## 1. 第一轮：等待期要有话说（用户点名的那一条）

新增 `HostActivity`（App 层）+ `ActivityDots`（自绘呼吸动效控件）：

- **常驻状态条**：固定高度，空闲显示「就绪 · 当前环节」，不忽隐忽现（忽隐忽现会让整页布局跳动）。
- **正在做什么**：大字标题，例如「正在请本机模型回答…」。
- **走到第几步**：流水线步骤（请模型回答 → 朗读），当前步用印泥红标出。
- **已经等了多久**：毫秒级计时器驱动，「已等待 3.2 秒」。
- **动效**：三个点依次明灭（纯代码构建的 Storyboard，离开视觉树自动停）。
- **失败与取消**：错误态用深印泥红，停留 8 秒后回到「就绪」；取消有独立文案（不是「已停止」）。

驱动点覆盖三处入口：提问、阶段提交后的播报、重播。状态条同时解决了「阶段按钮灰了但不知道为什么」。

## 2. 第二轮：界面层级与大屏可读性

- **右栏按阶段折叠**：纸笔汇总只在投票环节出现，揭秘区只在真相环节出现。
  此前它们常驻，把「揭秘」按钮挤到了屏幕外——**主持人必须滚动才能点到揭秘**。
- **状态提到栏首**：命令结果（已提交/被拒绝/缺确认）现在第一眼可见，不再藏在滚动区底部。
- **真相只显示一次**（验收报告 D6）：大屏展开完整时间线时，右栏那份窄列副本自动隐藏。
- **Markdown 清理**（D6）：`##` 标题、``` 围栏、扫描页码不再糊到桌面上。
- **复盘大屏的列网格**（D2）：`TruthDocument` 把真相拆成标题/等宽块/管道表/段落；
  `MonospaceGrid` 按**视觉空间**（汉字全角、西文半角）推导列参考线 —— 原文是按视觉对齐写的，
  字符下标推不出列（同一列在不同行里的字符下标并不相同）。
- 字体栈改为 `NSimSun, SimSun, monospace`（半角 0.5em / 全角 1.0em，天然的 2:1 栅格）。
- 音色下拉截断修复、重复状态行合并、交互区高度压缩。

## 3. 第三轮：功能缺口

| 缺口 | 处置 |
| --- | --- |
| `PendingMaterials` 在 VM 里存在但**从未绑定**——主持人看不到还剩几堆牌没发 | 右栏新增「待发放材料编号」与「还有 N 个编号未发放」 |
| 重启后没有「继续上一局」入口（验收报告 D7） | 首页新增可续玩卡片；每次回到首页重新计算，玩完了自动消失 |
| 首页没有剧本包时是死路 | 空状态给「先试一局演示剧本」按钮 |
| 演示剧本与真实剧本**各算各的存档 id**（`session-demo` vs `session-{包id}`） | `SessionIds` 收口到一处；同一局不会落到两个存档 |
| 设置页「读取模型列表」的自动保存会用旧快照覆盖主持台刚改的音色 | 抽出 `ResolveVoiceId()`，两条保存路径共用 |

## 4. 第四轮：再审一轮（67 条意见）

**两个 critical，都是本轮新写的代码**：

1. `TruthDocument.Parse` 遇到**行首带空格的标题**（`  ## 标题`）会**死循环**：
   标题判定用 `StartsWith("#")` 不匹配，段落收集又认领不了它，`index` 不前进。
   真相是在 UI 线程同步解析的 —— 遇到这种原文界面直接卡死。
2. `MonospaceGrid.MeasureOverride` **单位混算**：`maxWidth` 已经是像素，却整体又乘了一次字宽，
   期望宽度放大约八倍，大屏被撑出一片空白和多余横向滚动条。

**三个 high**：

3. 等宽块里的「07」「12」被当成扫描页码删掉 —— 那是真实数据，删了会缺列、列位错乱。
4. Edge-TTS 的**超时**与**用户取消**共用同一个 `OperationCanceledException` 通道：
   网络卡顿时主持人会看到「已停止播音」（他并没点停止），而且不降级、缓存还继续有效 5 分钟。
5. `RefreshVoices` 用「数量相同」判断无需刷新，且选中项失效后的兜底会让下拉框与实际朗读的音色不是同一个。

**其余按处理**：`IsUnlocked` 判定漂移（暂停态真相从提示词消失而屏幕还在显示）、
探测时持锁导致「停止播音」拿不到锁、启动等待探测把主窗口推迟最多 5 秒、
`ActivityDots` 的颜色 Setter 不会传到圆点上、`Storyboard` 离开可视树不停、
`SettingsStore` 临时文件名固定（双开实例互相覆盖）、损坏的 settings.json 被默认值覆盖、
正常退出也往 crash.log 写噪声等。

**自查时发现并修掉的**（工具没报、我自己走查出来的）：

- `_hadRevealedText` 在**每个**属性事件里都更新，`RefreshView` 先发 `PhaseTitle` 再发 `HasRevealedText`，
  跃迁被提前吃掉 → 揭秘后大屏**永远不会自动展开**。
- 状态条只在三条分支收尾，任何其它异常都会让它停在「正在朗读 / 已等待 N 秒」继续打 tick，
  而按钮其实已经放开了 —— 界面状态与真实状态正好相反。
- 播报的忙碌闸只覆盖了「命令触发」那一侧；主持台按钮发起的播报期间，阶段按钮仍可点，
  会并发跑两路模型与两段播音。
- `SessionViewModel.Session` 是从公共投影重建的，**没有 `ResumeState`**：
  「已揭秘后暂停」的一局，真相会从提示词里消失，而屏幕上还明明白白显示着真相。
- 真相块的列位在**字符空间**里聚类（错）：同一列在不同行里的字符下标并不相同，
  必须在视觉空间聚类。
