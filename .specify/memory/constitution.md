# AI 剧本杀 DM Constitution

## Core Principles

### I. 剧本保真与来源可追溯

必须完整处理获准的 PDF、图片及预解析材料，保留原文、文件指纹与页块来源。
关键角色秘密、主持规则、阶段条件、线索与结局必须有 SourceSpan。
既有 MinerU 等工具负责提取/OCR，应用负责完整续读、来源归一化及游戏可用性校验。
不得截断、以样例替换、推断凶手或补造缺失事实。
关键缺漏、矛盾、来源失配或未完成续读必须阻止开局，并输出脱敏报告。
正常准备不得要求本局玩家提前阅读真相；无法安全解决的问题交独立授权校验者或更换样本。
每局冻结所选剧本版本，正式游玩不重新运行 OCR。
导入向导中的流程可由主持模型依据组织者手册起草，经人工确认结构后视为有来源依据
（见 `docs/decisions/0004-import-wizard-ai-drafted-flow.md`）。

### II. 公共内容与秘密隔离

单电脑公共屏幕、TTS 与日志只能显示当前阶段已公开的信息。主持模型作为 DM，可读组织者手册（含真相）与线索卡，不读角色本；防剧透依靠主持提示词与揭秘状态，由人工试玩验收。
角色私密材料可在软件外的独立 PDF、纸本或编号包查看，或通过局域网平板按认领角色查看；平板发言全桌可见，不提供私下问答。
平板角色本默认以提取原文重新排版，不改写、不概括、不补写，保留章节、插图和原稿来源以供核对；识别完成、页覆盖完整与文字准确分别验证。
平板列出全部线索卡名称，已准备好的卡片由玩家点选即取得对应单卡，不按当前阶段限制访问。
卡片裁切或配对未可靠完成时暂停该组数字分发，不以整版图片替代单张。
角色本、组织者手册、真相和模型备忘不得混入平板公共消息投影；角色本仅由本人角色页接口提供，组织者手册原稿页仅由已认领会话的手册接口提供。
真相只有符合原本条件并明确确认揭秘后才能公开。
公共投影里的秘密必须在业务投影处隔离，不得仅靠 UI 隐藏或模型自审。角色本在 DM 上下文构造处隔离。
剧本文字、语音转写及模型输出都是数据，不能获得系统权限。
桌面 UI 不能直接持有完整真相对象；本机管理员可读本地文件不属于普通公共界面的隐私承诺。

### III. 确定性控制与可恢复状态

程序负责阶段迁移、材料包释放提示、投票汇总和原本结算；模型不得写游戏状态。
推进必须同时满足原本条件、预期 revision 和全员口头确认后的勾选。
投票提交与揭秘必须明确确认；不按超时、自然语言或模型建议自动执行。
原本没写清必须说明，不临场编规则或裁决。
唯一 operationId、单写入者及原子提交必须防止重复推进、重复材料发放及重复结算。
持久事件与快照绑定冻结剧本版本；恢复不自动重播或重复动作。
模型和 TTS 故障不得破坏已提交进度；重播只播放已保存公开文字。

### IV. 本机主持、局域网材料分发与按需语音

服务同一房间内 4–6 名真人，所有人均为玩家，以 Windows x64 独立桌面软件为主持中心。
从零自建，不复用 SoloPlay 源码；允许同局域网平板浏览器加入本局、认领角色、阅读私人材料、按名称点选线索卡、同步公共对话和当前环节，并在认领角色后发言（署名，与电脑输入框走同一个发送入口，不排队、不打断）。
仅使用本局浏览器会话，不建设账户、跨公网房间或 AI 玩家；公共主持和推进、揭秘、投票录入仍在电脑端，平板发言最多只能提议状态操作，纸质模式保留。
公共主持覆盖开场、规则、搜证、投票、结果及复盘，先完整支持一套固定剧本。
玩家按公共按钮，或向文字框打字、粘贴、点麦克风语音转文字后发送。
Windows Magpie 调用普通文字模型，独立 TTS 朗读；应用只在玩家点语音按钮后录音，音频只在内存、本机识别、识别完即丢，不得常开采音、不得上传音频、不得要求语音大模型。
普通发送不另弹转写确认；状态操作另行确认。
软件等待时不监听、不催促、不主动给提示、不自动推进、不建立多人问答队列。
纸笔投票汇总是最小默认，必须在开局时显式接受且原本允许，不假称单屏有电子秘密投票。

### V. 既有工具与实证交付

优先复用用户已有 Windows Magpie 和经过验证的文档工具，不复制其私密配置或供应商密钥。
接口、可用模型、工具版本、引擎及本地/远程处理边界必须按实际行为核实。
本机入口不等于离线推理；真实剧本外发必须取得明确允许，不静默启用远程 OCR。
不得公开提交真实剧本、秘密、凭据、存档或录音；第三方分发依赖仍须核查许可。
每阶段保存命令、实际结果和脱敏证据，区分已通过、未执行与受阻。
必须运行有意义的来源、防剧透、确认、幂等、恢复及取消测试，并实测 Windows 界面和发布物。
合成样本、Mock、HTML、构建或上游测试不能代替真实 4–6 人整局证据。

## 范围与技术约束

当前需求源为 specs/001-local-dm-mvp/spec.md，设计与任务分别由同目录 plan.md、tasks.md 管理。
旧 AI_DM_Research_and_Implementation_Plan.md 和历史 docs/plans 演进记录不得覆盖现行规格；本次平板范围变更按下文 ADR 0005 执行，并在实施前同步旧规格。
默认 Windows 原生桌面方案；采用模型、文档工具与 TTS 适配边界，允许进程内局域网页面服务，不引入公网服务或多租户基础设施。
平板演进的范围以 docs/decisions/0005-tablet-distribution-by-card-name.md 和 docs/plans/2026-10-21-tablet-distribution.md 为准；历史单端规格在实施前同步修订。范围获准不表示能力已经实现。
真实资料、运行状态和凭据存于用户私有位置，不能放安装目录或公共发布包。

## 开发流程与质量门禁

先完成 spec、research、data-model、contracts、plan 与 tasks，再按用户授权实施。
先以合成材料完成公共口播，再完成无剧透剧本准备、确定性完整局、语音输入及实际安装包。
文本 PDF、扫描 PDF、图片和完整续读分别验证，来源覆盖和语义保真不能互相替代。
每个阶段报告实测结果与阻塞，关键门禁未通过不得标记 Ready 或交付成功。
最终必须有目标 Windows 实机、所选私人材料路径及真实 4–6 人整局验收；平板模式还必须实测真实 iPad 与安卓平板浏览器（不限定品牌，各自设备上可用的浏览器即可）和发布物。

## Governance

本宪章约束规格、设计、任务和实现，执行同时遵守用户指令与适用 AGENTS.md。
修订记录原因、受影响原则与重新验证要求；不兼容原则或范围变更升主版本，新增原则升次版本，文字澄清升补丁版本。
本次 4.1.0 修订原则 I：导入向导中的流程由主持模型依据组织者手册起草、人工确认结构，
视为满足「阶段条件必须有来源依据」。放宽的理由是导入的人可能就是本局玩家，
读过手册即被剧透。受影响原则：I。代价与验证方式见
docs/decisions/0004-import-wizard-ai-drafted-flow.md。

本次 5.0.0 修订原则 II、IV 和技术范围：允许局域网私人材料分发，按用户决定取消线索卡阶段开放判断。角色本与主持模型的隔离、真相揭秘规则和电脑状态控制保留。代价是玩家可以提前打开卡片，何时点击交给玩家遵循规则。实施与重新验证要求见 ADR 0005；目前仅完成方案，真实平板验证尚未执行。

本次 6.0.0 修订技术范围：「应用不得采音、自建 ASR」作废，改为允许软件内置本机语音输入，条件是只在玩家点按钮后录音、音频只在内存、本机识别、识别完即丢、界面有明显的「正在听」。理由是外部 OpenLess 没有对外接口，软件拿不到结束信号。受影响原则：技术范围与隐私边界。代价与否掉的方案见 docs/decisions/0006-in-app-dictation-local-asr.md；重新验证要求：用 `--dictation-check` 实测识别速度与准确率，并在实机点一次麦克风。

本次 7.0.0 修订原则 IV 和技术范围：平板由“只读”改为可发言。条件：必须先认领角色，发言署名；平板发言与电脑输入框走同一个发送入口，AI 回应期间拒绝新发言，不排队、不打断；平板发言经意图识别只到提案，推进、揭秘、投票录入、压缩上下文仍只在电脑确认；平板不录音。受影响原则：IV、II（平板发言进入模型上下文，作为数据，无系统权限）。理由与否掉的方案见 docs/decisions/0007-tablet-live-chat.md。重新验证要求：并发测试（两块平板同时发送、电脑与平板同时发送、AI 回答中途平板发送，都只有一个请求被接受），并用真实 iPad 和安卓平板实测发言，记录设备型号、系统、浏览器版本和结果；通过前不得说功能完成。

本次 8.0.0 修订原则 II、IV 和技术范围：平板由“可发言”扩为同步显示整套公开界面（环节、环节列表、按钮状态、公开对话）。条件：不推送电脑屏幕画面；网页数据只取自业务层的只含公开内容的“平板界面投影”，秘密在投影处隔离而不是靠网页隐藏；推进、放出材料、提交投票、揭秘、结束、暂停/继续在平板上只显示成灰色占位，平板能点的仍只有发送和停止朗读；备忘、上下文占用等内部状态不显示。受影响原则：II、IV。理由与否掉的方案见 docs/decisions/0008-tablet-ui-mirror.md。重新验证要求：防泄露测试（真相、备忘、上下文占用、角色本、手册任何一项出现在投影里都算失败），并用真实 iPad 和安卓平板各实测整套界面，记录设备型号、系统、浏览器版本和结果；通过前不得说功能完成；7.0.0 的发言实测要求同样未完成。

本次 9.0.0 修订原则 II：平板加「组织者手册」页签，已认领角色的会话可逐页翻手册原稿（含真相页），不设 PIN 与组织者身份，靠玩家自觉。条件：只给已认领会话，无会话或未认领 404；只读原稿页，不重排文字、不记进度；手册不进入公共消息投影与卡目录。受影响原则：II。理由与否掉的方案见 docs/decisions/0009-tablet-handbook-tab.md。重新验证要求：投影防泄露测试照旧；真实 iPad 与安卓平板各翻一次手册页签并记录；通过前不得说功能完成。
